# Group failure request: public path not reachable
The exact Netty common 4.2.10.Final group implementation is MultithreadEventExecutorGroup.java. Its constructor installs a listener on each child's terminationFuture (lines117-125). When terminatedChildren reaches children.length, that listener unconditionally calls terminationFuture.setSuccess(null). It does not propagate child failure to the group future. MultiThreadIoEventLoopGroup inherits this behavior. QuicTransport owns this concrete group and offers no replacement-group API. Thus no public transport call produces a failed group termination result, even if an individual loop fails; a group-failure fixture would need to mutate its promise or replace its private dependency. Neither represents public transport behavior. This part of gap2 is refuted, rather than tested by changing another component's private state.

Primary source: https://github.com/netty/netty/blob/netty-4.2.10.Final/common/src/main/java/io/netty/util/concurrent/MultithreadEventExecutorGroup.java#L117
The real multiple-child and parent error outcomes are covered separately by F93cQuicMultipleCloseFailuresTest. This source observation does not claim that all event-loop errors are harmless.
