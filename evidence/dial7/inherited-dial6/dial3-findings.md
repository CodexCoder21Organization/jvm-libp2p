## 2026-10-19 00:00 UTC — N1 mechanism and deterministic fixture design
OBSERVED: Fork develop 031e565a differs from snapshot-25 in NoiseXXSecureChannel.kt only at the already-fixed outbound write-failure forwarding. Both choose one global first-four decision in the constructor. The mechanism is that two pending handshakes on the same event loop both qualify for inline computation under that global count, so holding one computation prevents the loop from delivering the other connection's ready callback; the evidence that demonstrates this is the constructor's global threshold and enqueueCrypto's synchronous inline branch, to be verified by the gated public-host proof below.
Plan for the proof: two actual loopback client connections to one relay in a fresh one-loop child JVM; a public SecureChannel wrapper installs inbound gates before delegating to Noise. Both relay handshakes are installed before either gate releases its first frame. Release first and second gates in FIFO loop tasks. A per-channel computation observer holds the first responder computation until the second ready callback (bounded only for test cleanup); assert that callback observes first computation unfinished. This fixes the ordering rather than asking a host to produce a race. No existing test changes; sequential-inline scenarios remain byte-identical.
