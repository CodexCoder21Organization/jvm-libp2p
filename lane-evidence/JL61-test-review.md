## Coverage that is present

The current tests cover the main Netty state transitions with real TCP connections using Noise and Yamux: first close failure, ordinary close retaining its original result, retry beginning before any close, retry sharing a pending original attempt, repeated settled failures followed by recovery, successful retry becoming terminal, caller-future mutation isolation, many concurrent retry callers sharing one held physical attempt, re-entry from the retry handler and failure callback, and peer closure before retry. `ParentCloseOwnershipTest` also checks connection/network close sharing while pending and sharing an initial failure.

## Findings

1. **The first physical dispatch is not tested for re-entry.** [ConnectionCloseRetryTest.kt:221](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ConnectionCloseRetryTest.kt:221) starts with `connection.close()` and only re-enters from the handler after the first attempt has failed and the retry attempt is being submitted. [ConnectionCloseRetryTest.kt:82](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ConnectionCloseRetryTest.kt:82) and [ConnectionCloseRetryTest.kt:98](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ConnectionCloseRetryTest.kt:98) cover first-time retry with an immediately successful or failed handler, but neither re-enters while that initial physical close is being dispatched. Since initial state publication and retry-candidate publication are separate paths, add a deterministic handler re-entry test for the first `retryClose()` call and assert exactly one physical request. The parent said this case is being added; it was absent in the snapshot I reviewed.

2. **The inherited default implementation has no behavior test.** [Connection.kt:19](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/main/kotlin/io/libp2p/core/Connection.kt:19) documents that implementations without retained failures inherit `retryClose() = close()`. Every test fixture in [ConnectionCloseRetryTest.kt:268](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ConnectionCloseRetryTest.kt:268) constructs TCP hosts and casts to `ConnectionOverNetty`, which overrides the default. `RelayTransport.ConnectionOverStream` at `RelayTransport.java:95` inherits the default and delegates ordinary close to `stream.close()` at `RelayTransport.java:159`; no test invokes `retryClose()` on that real stream-backed implementation. Add a relay-path assertion that inherited retry close delegates to the stream close behavior and remains idempotent. The KDoc accurately states the delegation and override rule. It does not itself prove binary compatibility with an already-compiled implementor; if that compatibility claim is a release requirement, a binary fixture or ABI check is separate evidence from compiling current sources.

3. **A failed executor-cleanup assertion skips release of the held close promise.** In [ConnectionCloseRetryTest.kt:181](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ConnectionCloseRetryTest.kt:181), `awaitTermination` is asserted before unresolved `ChannelPromise`s are completed at line 184. If the assertion fails, the held physical close is never released, which can leave the fixture's channel and test executor work behind for later tests. Release outstanding promises in an unconditional `finally` path, then report executor termination.

4. **Recovery after a transport/network-owned failure is not covered.** [ParentCloseOwnershipTest.kt:49](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ParentCloseOwnershipTest.kt:49) starts a pending close through `network.close()`, then checks that `connection.close()` shares it. The failure case starts with `parent.close()` and only checks that `network.close()` observes that original failure at [ParentCloseOwnershipTest.kt:104](/tmp/claude-501/-code/2abf611d-5e04-4919-84a8-d7b72869d40c/scratchpad/workspace/JL61/libp2p/src/test/kotlin/io/libp2p/transport/ParentCloseOwnershipTest.kt:104). There is no inverse recovery sequence in which transport/network close starts and fails, then `connection.retryClose()` retries the same channel while later ordinary owners continue to observe the original result. That cross-owner path is worth covering because the API contract is phrased in terms of the latest failed close attempt, regardless of which ordinary owner began it.

## Limits of this review

This was a static test review. I did not verify test pass rates, formatter output, wall-clock bounds, ABI compatibility, or the parent’s in-progress cleanup and re-entry changes. Those should be rechecked against the final diff. The real TCP/Noise/Yamux path and controlled Netty close failures are present; the untested areas above concern initial-dispatch re-entry, the inherited non-Netty API path, failure cleanup, and retrying after another owner initiated the failed attempt.
