Mechanism to fix: the per-channel close owner retains its failed result forever, and Connection offers no explicit path to submit another physical close. Reproducer: real TCP/Noise/Yamux peers with a Netty outbound handler failing the first physical close, then permitting close; ordinary close retains its failure while the explicit operation must submit attempt two and close the socket.

Invariant table (before implementation):
| Resource/state | Creator/owner | Close/public result | Re-entry/concurrency/mutation/restart | Test |
|---|---|---|---|---|
| Original close operation | first connection/transport caller; per-channel private owner | ordinary close always observes original result | publish before handlers; derived futures prevent mutation; channel lifetime, no persisted state | existing ParentCloseOwnershipTest + retry success still retains original failure |
| Initial retry with no ordinary close | first explicit caller | starts same initial close operation | ordinary close and retry share pending operation | retry-first/pending-original |
| Retry after settled failure | explicit caller winning CAS | new independent physical operation | callers observing it pending share it; publish before handler callback | held retry + 64 concurrent callers + re-entry |
| Retry failures | current private attempt, original retained separately | each explicit call after failure may retry; ordinary result unchanged | failure callbacks can immediately re-enter; retain only first/latest, no history list | repeated failures + failure callback |
| Successful physical close | channel; successful attempt terminal | later retry successful without physical request | externally closed channel no-op; listener ordering preserved | retry after success / peer closure |
| Caller future | caller only | may cancel/complete its observation | cannot mutate owner or peers; retry observer cancellation cannot start new attempt | held retry observer mutation |
