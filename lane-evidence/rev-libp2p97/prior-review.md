### U1 — P1 against the requested guarantee — Unreleased hold can retain an unused parent indefinitely

INFER: Locations: upstream libp2p/src/main/kotlin/io/libp2p/network/ConnectionSelection.kt:149-152, 213-222 and 63-66. Rule: brief item 3; CODE_REVIEW / Unbounded Inputs and Variable-Size Data Without a Scale Test; TESTING / Load, Saturation, and Soak.

OBSERVED: Acquiring a hold increments provisionalUses. Only use.close (or child cancellation/failure closing the hold) decrements it. A hold acquired without a child has no owner-lifecycle callback, expiry or configured allowance. If its caller returns without closing it, duplicate retirement keeps seeing a nonzero use count. The documented API does require callers to close holds; it does not promise automatic cleanup when callers disappear. The brief asks for that stronger guarantee, which the current API and evidence do not supply. The 23 capacity controls test child outcomes, not hold ownership.

INFER: Reproducer sketch: use the existing real two-parent public setup, acquire a hold on the unused parent in a worker, then let the worker return without opening a child or closing the hold. Settle the dial on the other parent and require unused-parent retirement. Repeat against a small configured parent/hold allowance and both multiplexers. There is no public configured allowance today and no automatic owner-end event, so this property cannot be certified by the current controls. This is an explicit brief/contract gap, not a claim that the documented caller-close rule promises automatic recovery.
